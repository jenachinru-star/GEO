### 阶段 2：配额检查（1 天）

**检查位置**：在 `adapter.query()` 方法内部、真正发 HTTP 请求**之前**。

**检查逻辑**：

```
1. 从 usage_context 读 user_id
   - 如果没有 user_id（系统定时任务、worker）→ 跳过配额检查
   - 如果 user_id 存在 → 继续

2. 查 user_quota 表，拿该用户的配额配置
   - monthly_token_limit = -1 → 无限额，跳过检查

3. 查当月已用token：
   SELECT COALESCE(SUM(total_tokens), 0) 
   FROM geo_llm_usage_log 
   WHERE user_id = ? AND created_at >= 本月1号

4. 比较：
   - 已用 >= 限额 → 抛异常/返回失败："本月AI用量已达上限（xx/xx tokens），请联系管理员"
   - 已用 >= 限额 × 80% → 正常调用，但在返回结果里带一个 warning 标记
   - 否则 → 正常调用
```

**不做限流（RPM/TPM）**—— 按你的要求，现在只做月度配额。

**用户模型开关检查**：

```
在 adapter.query() 内部：
1. 从 usage_context 读 user_id
2. 查 user_platform_pref，看该用户是否启用了这个 platform
3. 如果没启用 → 返回失败："您已关闭此AI模型，请在设置中启用"
4. 如果管理员也全局停用了（Platform.status=false）→ adapter_factory 根本不会创建它，自然不会被调到
```
