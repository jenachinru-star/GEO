## 4. 遇到的问题和解决方式

1. **默认 python 无 SQLAlchemy**：系统 PATH 中的 `python` 是 Doubao sandbox runtime，缺少项目依赖。解决：统一使用 `C:\Users\jenac\miniconda3\python.exe` 执行所有后端命令。
2. **A2 手册代码有笔误**：手册 after 代码中 while 循环引用了未定义的 `user.username` 和 `unique_username`。解决：按正确逻辑实现（先计算 unique_username 再创建 User），功能等价。
3. **A5 monitor_record 用户隔离复杂度**：monitor_record 的 question_id 实际存储 semantic.id（医生 GEO 场景），简单按 Question.user_id 过滤会漏掉语义库数据。解决：通过 `question_id IN (用户 Question IDs + Semantic IDs)` 实现完整隔离。
4. **B5 字段名与手册不一致**：手册建议加 priority/sort_order/is_builtin/config_json，实际代码引用的是 priority/timeout/max_tokens/temperature/description/platform_type/extra_config。解决：按实际代码引用补全字段，DB 表已有这些列无需迁移。
5. **C3 手册路径重复问题**：手册 after 写 `request.get('/geo/api/v1'+url)`，但 request 实例已有 baseURL='/geo/api/v1'，会导致路径重复。解决：改为 `request.get(url)`，同时因响应拦截器返回 response.data，.then () 回调参数相应调整。
6. **D1 表列名与手册不一致**：手册用 record_date/platform，实际为 detect_date/platform_code，且实际约束还含 detect_round。解决：按实际列名修改迁移脚本和模型。
7. **D2 模型无 timeout_seconds 字段**：手册代码引用 task.timeout_seconds，实际 AsyncTask 模型无此字段。解决：使用全局 TASK_TIMEOUT_SECONDS=600 常量。
