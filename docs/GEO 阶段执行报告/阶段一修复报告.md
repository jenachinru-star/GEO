## 2. 每项改动说明

### Bug 1（P0）：排队超时时区 bug

**文件**：`backend/app/worker/worker.py`

表格

| 行号 | before           | after               | 说明                                                         |
| ---- | ---------------- | ------------------- | ------------------------------------------------------------ |
| 123  | `datetime.now()` | `datetime.utcnow()` | 排队超时检查：task.created_at 存的是 UTC，必须用 utcnow () 比较，否则本地时间 (UTC+8) 与 UTC 差值 = 8 小时 > 600 秒，任务一创建就被判超时 |
| 127  | `datetime.now()` | `datetime.utcnow()` | 同一函数内标记 failed 时的 finished_at，保持时区一致         |

**根因**：`task.created_at` 由 SQLAlchemy `server_default=func.now()` 存储为 UTC 时间，而 `datetime.now()` 返回本地时间（UTC+8），差值恒为 8 小时（28800 秒），远超 600 秒超时阈值。

### Bug 2（P1）：语义延伸无 failover

**文件**：`backend/app/engines/semantic_extender.py`

表格

| 改动   | 位置                                                 | 说明                                                         |
| ------ | ---------------------------------------------------- | ------------------------------------------------------------ |
| 修改 1 | 原 `_get_adapter()` (145-151 行) → `_get_adapters()` | 返回所有已启用平台的 `(code, adapter)` 列表，按优先级顺序，用于 failover 遍历 |
| 修改 2 | `_generate_synonyms()` (100-115 行)                  | 加入平台 failover 循环：遍历所有平台，成功且解析出问题则返回，失败 / 异常则 continue 尝试下一个，全部失败才返回空 |
| 修改 3 | `_generate_deep()` (117-143 行)                      | 同样加入平台 failover 循环，逻辑与同义变体一致；specialty 检查提前到获取 adapters 之前 |

**核心变化**：从 "只取第一个平台 (deepseek)，失败直接返回空" 改为 "按优先级遍历所有平台 (deepseek→glm→minimax→doubao)，逐个尝试，成功即返回"。

### Bug 3（P1）：导出文件名乱码

**文件**：`frontend/src/api/index.ts`

**根因**：文件中中文字符串被错误编码（UTF-8 字节被当成 GBK 解码后再存为 UTF-8），导致硬编码的注释、文件名和提示消息全部是乱码。

**改动量**：共修复 **34 处**中文乱码（手册表格列出 12 处，实际全文件有 34 处，包括所有 API 分区注释、导出文件名、提示消息）。

关键修复项：

- 导出文件名：`监测记录_`、`监测问题_`、`知识库_`、`内容资产_`、`GEO完整报告_`、`GEO医生报告_`
- 提示消息：`导出成功`、`导出失败`
- API 分区注释：`请求拦截器`、`响应拦截器`、`仪表盘`、`监测中心`、`内容资产`、`知识库`、`竞品`、`RAG问答`、`系统`、`数据导出`、`认证`、`医生Profile`、`语义库`、`文章管理`、`实体一致性`、`文章模板`、`文章分发`、`工具配置`、`异步任务`、`内容机会`
- 其他：`GEO/AEO采集可能需要1-3分钟`、`导出是文件下载，需要单独处理（blob响应类型，不走统一拦截器）`

**修复方法**：先用 GBK→UTF-8 自动转换修复纯 CJK 序列（12 处），再用精确字符串映射修复含 `?` 替换符和 Private Use Area 字符的残留序列（22 处）。
