## Bug 1（P0）：GEO 刷新任务创建后立即被标记"排队超时"，永远不会执行

### 现象

用户点击 GEO 刷新后，任务创建成功（返回 200），但 19 秒后被标记为 failed，错误信息"任务排队超时"。任务实际从未执行。

### 根因

`backend/app/worker/worker.py` 第 123 行的排队超时检查存在时区不一致 bug：

```python
# 当前代码（worker.py:123）
if task.created_at and (datetime.now() - task.created_at).total_seconds() > TASK_TIMEOUT_SECONDS:
```

- `task.created_at` 存储的是 **UTC 时间**（如 12:15:28）
- `datetime.now()` 返回的是**本地时间**（UTC+8，如 20:15:28）
- 差值 = 8 小时 = 28800 秒 > 600 秒（TASK_TIMEOUT_SECONDS）
- 结果：任务一创建就被判定为排队超时，直接标记 failed，永远不会执行

### 修复

**文件**：`backend/app/worker/worker.py`

**修改 1**（第 123 行）：
```python
# before
if task.created_at and (datetime.now() - task.created_at).total_seconds() > TASK_TIMEOUT_SECONDS:

# after
if task.created_at and (datetime.utcnow() - task.created_at).total_seconds() > TASK_TIMEOUT_SECONDS:
```

**修改 2**（第 127 行，同一个函数内）：
```python
# before
task.finished_at = datetime.now()

# after
task.finished_at = datetime.utcnow()
```

## Bug 2（P1）：语义延伸（semantic_extender）没有平台 failover，deepseek 故障时返回空结果

### 现象

用户在语义库点击"延伸"某个语义，接口返回 200 但延伸结果为空。后端日志显示 deepseek 返回 503，但没有自动切换到 glm/doubao。

对比：语义生成（semantic_generator）在阶段一中已经加了 failover，deepseek 失败会自动切换 glm。但语义延伸（semantic_extender）漏掉了。

### 根因

`backend/app/engines/semantic_extender.py` 第 145-151 行的 `_get_adapter()` 只取第一个平台（deepseek），失败后不尝试其他平台：

```python
def _get_adapter(self):
    if self.platform_code:
        return adapter_factory.get_adapter(self.platform_code)
    platforms = adapter_factory.get_enabled_platforms()
    if platforms:
        return adapter_factory.get_adapter(platforms[0])  # ← 只取 deepseek
    return None
```

`_generate_synonyms()`（第 100-115 行）和 `_generate_deep()`（第 117-143 行）都调用 `_get_adapter()`，deepseek 失败后直接返回空列表，不尝试其他平台。

### 修复

**文件**：`backend/app/engines/semantic_extender.py`

**修改 1**：把 `_get_adapter()` 方法替换为 `_get_adapters()`，返回所有已启用平台的适配器列表：

```python
# before（第 145-151 行）
def _get_adapter(self):
    if self.platform_code:
        return adapter_factory.get_adapter(self.platform_code)
    platforms = adapter_factory.get_enabled_platforms()
    if platforms:
        return adapter_factory.get_adapter(platforms[0])
    return None

# after
def _get_adapters(self):
    """返回所有已启用平台的适配器列表（按优先级顺序），用于 failover"""
    if self.platform_code:
        adapter = adapter_factory.get_adapter(self.platform_code)
        return [(self.platform_code, adapter)] if adapter else []
    platforms = adapter_factory.get_enabled_platforms()
    adapters = []
    for code in platforms:
        adapter = adapter_factory.get_adapter(code)
        if adapter:
            adapters.append((code, adapter))
    return adapters
```

**修改 2**：修改 `_generate_synonyms()` 方法（第 100-115 行），加入平台 failover 循环：

```python
# before（第 100-115 行）

            return []

        logger.error(f"同义变体生成异常: {e}")
        return []

# after
def _generate_synonyms(self, question: str) -> List[str]:
    """用LLM生成同义变体（带平台 failover）"""
    adapters = self._get_adapters()
    if not adapters:
        return []

    user_prompt = f"原问题：{question}\n\n请生成这个问题的同义变体（3-5个）。"
    for code, adapter in adapters:
        try:
            result: QueryResult = adapter.query(user_prompt, system_prompt=self.SYNONYM_SYSTEM_PROMPT)
            if result.success:
                questions = self._parse_questions(result.answer)
                if questions:
                    logger.info(f"同义变体生成使用平台: {code}")
                    return questions
            else:
                logger.warning(f"同义变体平台 {code} 调用失败: {result.error}，尝试下一个平台")
        except Exception as e:
            logger.warning(f"同义变体平台 {code} 异常: {e}，尝试下一个平台")
    logger.warning("同义变体所有平台均失败")
    return []
```
