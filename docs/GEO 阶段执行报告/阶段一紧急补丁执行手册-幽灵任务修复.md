## 问题背景

### 幽灵任务的根本原因

main.py 启动了 **2个 worker 线程**（geo-worker-0, geo-worker-1），每个都运行 `run_worker_loop()`：

```
worker-0: 认领任务#19 → execute_task() 阻塞在采集循环中（19个语义×4平台串行，约36分钟）
worker-1: 空闲轮询 → 每3秒调用 recover_stuck_tasks() → 600秒后发现任务#19超时 → 把数据库状态改成 failed
```

**worker-0 完全不知道任务被标记为failed，继续执行、继续写数据库。** 这就是幽灵任务。

### 为什么100%超时

- 19个语义 × 4平台串行 × 平均30秒/平台 = 约36分钟
- 但任务超时只有 600秒（10分钟）
- 加上 deepseek 503 时双重重试（SDK 3次 + collector层2次 = 6次），每个语义浪费约10秒

```python
def complete_task(db: Session, task: AsyncTask, result: dict = None, error: str = None):
    """完成任务（成功或失败）"""
    # 状态防御：已经是终态的任务不允许再改
    if task.status in ("succeeded", "failed", "cancelled"):
```

```python
def recover_stuck_tasks(db: Session):
    """恢复卡住的任务（running超过超时时间的标记为cancelling，由执行线程自行终止）"""
    now = datetime.now()
    running_tasks = db.query(AsyncTask).filter(
        AsyncTask.status == "running",
        AsyncTask.started_at.isnot(None)
    ).all()

    for task in running_tasks:
        timeout = get_task_timeout(task.task_type)
        elapsed = (now - task.started_at).total_seconds()
        if elapsed > timeout:
            logger.warning(f"任务 #{task.id} 超时（type={task.task_type}, elapsed={elapsed:.0f}s > {timeout}s），标记为cancelling")
            task.status = "cancelling"
            task.error_message = f"任务执行超时（>{timeout}秒），正在取消..."
            task.progress_message = "任务超时，正在取消..."
    db.commit()
```

```python
def query_single_platform(self, platform_code: str, question: str,
                           retries: int = 1) -> tuple[bool, str]:
    """向单个平台提问，带重试和熔断（retries=1表示只尝试1次，重试由SDK层负责）"""
    # 熔断检查：如果平台已被标记为故障，本次采集剩余语义直接跳过
    if platform_code in self._failed_platforms:
        logger.info(f"平台 {platform_code} 已熔断，跳过")
        return False, f"平台 {platform_code} 本次采集中已故障，跳过"

    adapter = adapter_factory.get_adapter(platform_code)
    if not adapter:
        return False, f"平台 {platform_code} 未配置"

    last_error = "未知错误"
    for attempt in range(retries):
        try:
            if attempt > 0:
                wait = (2 ** attempt) + random.uniform(0, 1)
                logger.info(f"重试 {platform_code}，等待 {wait:.1f}s")
                time.sleep(wait)

            logger.info(f"调用 {platform_code} API: {question[:50]}...")
            result = adapter.query(question)

            if result.success:
                logger.info(f"{platform_code} 调用成功，回答长度: {len(result.answer)}")
                return True, result.answer
            else:
                last_error = result.error or "未知错误"
                logger.warning(f"{platform_code} 调用失败: {last_error[:200]}")
                if attempt < retries - 1:
                    continue
                # 调用失败，标记熔断（本次采集剩余语义跳过此平台）
                self._failed_platforms.add(platform_code)
                logger.warning(f"平台 {platform_code} 连续失败，本次采集剩余语义将跳过此平台")
                return False, last_error
        except Exception as e:
            last_error = f"{type(e).__name__}: {str(e)}"
            logger.error(f"{platform_code} 调用异常: {last_error}")
            if attempt < retries - 1:
                continue
            # 调用异常，标记熔断
            self._failed_platforms.add(platform_code)
            logger.warning(f"平台 {platform_code} 连续异常，本次采集剩余语义将跳过此平台")
            return False, last_error

    return False, last_error
```

## 修复4（P1）：移除双重重试

这个修复已经包含在修复3.2中了——`query_single_platform` 的 `retries` 默认值从 `2` 改成了 `1`。

**原理**：
- 修复前：collector层重试2次（2次尝试）× SDK层重试2次（3次尝试）= 最多6次请求
- 修复后：collector层重试1次（1次尝试）× SDK层重试2次（3次尝试）= 最多3次请求

SDK层的重试保留（因为它有指数退避，更合理），去掉collector层的额外重试。
