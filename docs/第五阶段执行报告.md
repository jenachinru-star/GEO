## 一、启动验证问题答案

1. **PUBLISH_PLATFORM_NAMES**：原有6个平台（wechat/xiaohongshu/zhihu/video/douyin/other），定义在 `frontend/src/store/useStore.ts` 第80-87行。
2. **ArticleDraft模型**：字段为 id, user_id, semantic_id, title, content, platform, status, entity_consistent, created_at。**没有** publish_url 或 distributed_platforms 字段。
3. **article.py API**：6个端点（GET列表、POST创建、GET详情、PUT更新、DELETE删除、POST校验），前缀 `/api/v1/article`。
4. **Create.tsx平台选择**：使用 antd `Select` 组件，数据来自 `PUBLISH_PLATFORM_NAMES`（useStore.ts导出的 Record<string,string>）。
5. **main.py路由注册顺序**：monitor→content→knowledge→competitor→dashboard→rag→system→export→auth→doctor→semantic→geo→article→entity→tools。新路由加在 tools_router 之后。
6. **database.py模型导入**：通过 `from app.models import platform, question, monitor, ...` 批量导入后执行 `Base.metadata.create_all`。新增模型需在import列表中添加。
7. **schemas字段**：ArticleCreate = {semantic_id, title, content, platform, status}；ArticleOut = {id, user_id, semantic_id, title, content, platform, status, entity_consistent, created_at}。
8. **前端articleApi**：getList, create, getDetail, update, delete, validate 共6个方法。
9. **DoctorProfile模型**：字段为 id, user_id, real_name, title, province, city, hospital, department, specialty, awards, case_history, self_intro_template, created_at, updated_at。生成llms.txt需要 real_name, title, hospital, department, province, city, specialty, awards, case_history。

**额外确认**：MonitorRecord 模型有 `cite_count` 字段（Integer, default=0），任务5AEO判断使用 `cite_count > 0`。

## 五、遇到的问题和解决方案

| 问题 | 解决方案 |
|------|----------|
| PowerShell 不支持 `&&` 操作符 | 使用 `cmd /c "cd /d path && command"` 方式执行 |
| Profile.tsx 使用 `Space` 组件但未导入 | 在 antd import 中添加 `Space` |
| DataCenter.tsx 使用 `Select` 组件但未导入 | 在 antd import 中添加 `Select` |
| 测试用JWT token缺少 `exp` 字段，verify_jwt 返回 None | 生成token时添加 `exp` 和 `iat` 字段（与 IAMService.generate_jwt 一致） |
| semantic API 返回 data 为 list 而非 dict（无分页） | 测试脚本中兼容两种返回格式 |
| 执行手册中任务4的llms.txt端点建议"在template.py中添加" | 直接在 template.py 中实现了 /template/llms.txt 端点，未单独新建 api/llms.py |
| 执行手册任务5代码使用 question_id 过滤 | 现有 geo.py 代码统一使用 semantic_id 过滤（医生维度记录 semantic_id 已冗余存储），保持代码一致性使用 semantic_id |
