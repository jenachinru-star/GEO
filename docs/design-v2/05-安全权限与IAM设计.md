# 安全、权限与 IAM 设计

## 1. 安全目标

1. 任意用户不能访问其他 Workspace 数据。
2. 禁用用户和撤销会话能够立即或在可控时间内生效。
3. 上游 IAM 身份使用不可变标识绑定。
4. 模型费用、导出、发布和管理操作受权限、配额和审计约束。
5. 医生资料、内容和潜在医疗敏感信息按最小必要原则处理。

## 2. 威胁边界

主要风险：伪造/窃取会话、用户名碰撞绑定、跨租户 IDOR、旧全局模块泄漏、批量调用消耗模型预算、恶意内容 Prompt Injection、导出公式注入、外部 URL 协议注入、日志泄密、Webhook 伪造、管理员密钥暴露。

## 3. IAM 登录流程

### 3.1 推荐流程

1. 前端访问 /auth/login；
2. 后端生成高熵 state、nonce，支持时生成 PKCE；
3. state 记录到共享存储，包含过期、原始跳转地址和一次性状态；
4. 浏览器跳转 IAM；
5. IAM 回调后端；
6. 后端原子消费 state，使用 code 换 token；
7. 校验 issuer、audience、nonce、过期和签名；
8. 以 provider + sub 查找用户；
9. 检查用户状态并同步允许更新的显示字段；
10. 创建服务端会话，设置 HttpOnly、Secure、SameSite Cookie；
11. 只跳转经过白名单验证的前端相对路径。

不得用 preferred_username 作为身份唯一键；不得把上游 token 或平台 JWT 放在 URL 查询参数长期暴露。

### 3.2 会话

推荐服务端 Session Cookie。Session 保存 user_id、token_version、创建/过期时间、最后活动时间和撤销时间。

若短期必须继续 JWT：使用短有效期访问令牌、HttpOnly Cookie、服务端 token_version 和撤销检查。禁止使用公开默认密钥，生产密钥应至少 256 bit 随机并可轮换。

### 3.3 注销

注销必须服务端撤销 Session、清 Cookie、记录审计。是否同时退出 IAM 由产品提供“退出本系统”和“退出统一账号”两个明确动作，避免用户退出后自动重新登录。

## 4. Workspace 权限

### 4.1 角色矩阵

| 操作 | owner | editor | reviewer | viewer |
|---|:---:|:---:|:---:|:---:|
| 查看 Dashboard/结果 | 是 | 是 | 是 | 是 |
| 修改医生资料 | 是 | 是 | 否 | 否 |
| 管理语义问题 | 是 | 是 | 否 | 否 |
| 创建采集任务 | 是 | 是 | 否 | 否 |
| 创建/修改草稿 | 是 | 是 | 可评论 | 否 |
| 医学/合规审核 | 可配置 | 否 | 是 | 否 |
| 发布内容 | 是 | 按授权 | 否 | 否 |
| 导出数据 | 是 | 按授权 | 否 | 否 |
| 管理成员 | 是 | 否 | 否 | 否 |

平台 admin 只能通过专用后台执行跨 Workspace 操作，且所有读取、导出和代操作必须记录审计原因。

### 4.2 防止 IDOR

所有资源查询同时使用 workspace_id 和 resource_id。先查资源再在 Python 判断 owner 的写法容易遗漏，不推荐。404 与 403 的策略保持一致，避免枚举其他 Workspace 资源。

自动化测试必须创建两个 Workspace，逐个覆盖读、写、删除、导出和任务接口。

## 5. 旧模块隔离

旧 Question、Content、Knowledge、Competitor、MonitorRecord 缺少 Workspace 所有权。处理顺序：

1. 普通用户导航移除；
2. 普通用户路由返回 404/410 或功能未启用；
3. 写接口关闭；
4. 仅平台管理员通过专用 Legacy 页面查看；
5. 完成所有权识别后迁移；
6. 不可识别数据归档，不分配给任意用户。

不能因为接口带 Depends(get_current_user_id) 就认为完成隔离。

## 6. 输入与输出安全

### 6.1 Schema

- 所有字符串设置合理长度；
- 枚举使用 Literal/Enum；
- ID 使用正数或 UUID；
- page_size 有上限；
- URL 只允许 http/https；
- 文件类型、大小和内容分别检查；
- 禁止把请求 dict 直接 setattr 到 ORM。

### 6.2 HTML/富文本

若内容编辑器支持 HTML，后端白名单清洗标签与属性，前端展示也采用可信 Sanitizer。Markdown 渲染禁用原始 HTML 或严格清洗。

### 6.3 导出

对以 =、+、-、@、制表符或回车开头的用户文本加安全前缀；工作表名和文件名清洗；禁止包含其他 Workspace 数据。

### 6.4 外链

拒绝 javascript、data、file 等协议。前端新窗口打开使用 noopener/noreferrer。后端若主动检查 URL，防止 SSRF：阻止内网、环回、云元数据地址，限制重定向与响应大小。

## 7. LLM 安全

- 把用户内容、模型回答和外部网页视为不可信数据；
- 系统指令与不可信文本明确分隔；
- 分析模型只能输出受 Schema 限制的结构；
- 工具调用使用服务器允许列表，模型不能任意构造 URL 或数据库操作；
- 不向分析模型传送不必要的个人信息；
- 不保存 reasoning_content 作为用户答案；
- 原始回答展示前过滤潜在脚本和危险链接；
- Prompt 与分析器版本可审计。

## 8. 密钥与配置

- 密钥仅存环境变量或 Secret Manager；
- 前端构建变量中不得出现 Provider 密钥；
- 日志和异常不得输出密钥；
- 管理员接口只返回 configured=true/false；
- 密钥支持轮换；
- 开发、测试、生产完全分离；
- .env、数据库备份和导出目录不提交 Git。

## 9. 限流、配额和滥用防护

限制维度：IP 登录频率、用户 API 频率、Workspace 并发 Run、每日 Observation、Provider 并发、导出频率、内容生成次数和 Webhook 失败次数。

创建任务前预估成本并预占额度；任务结束按实际使用结算，失败按策略释放。重复 Idempotency-Key 返回原任务。

高成本操作需要明确确认，不允许 scan 参数解析失败后退化成全量扫描。

## 10. Webhook 安全

- 使用每个工具独立密钥验证 HMAC 签名；
- 校验时间戳和重放窗口；
- event_id 唯一，重复事件幂等处理；
- 回调快速返回，后续处理入队；
- 状态只能按允许方向推进；
- 原始负载按保留策略存储并脱敏；
- 连续失败告警和暂停。

## 11. 审计与隐私

### 11.1 审计

记录登录、资料修改、成员变更、任务触发、人工纠错、内容审核、发布、导出、平台配置和管理员代操作。

审计日志普通用户不可修改。高风险管理员查询需要目的和工单/备注。

### 11.2 数据最小化

当前产品不需要患者姓名、联系方式、病历、影像或诊断记录，页面和接口不得诱导录入。用户误填敏感信息时应提供删除和纠正流程。

### 11.3 保留与删除

建议定义：上游原始回答、内容版本、审计日志、任务错误和导出文件各自保留期。Workspace 删除采用申请、等待期、导出、级联清理和审计，而不是直接同步删除所有数据。

## 12. 安全验收

- [ ] 生产无默认密钥；
- [ ] IAM 使用 provider+sub；
- [ ] state/nonce 可跨进程且一次性；
- [ ] 会话可服务端撤销；
- [ ] 所有 V2 资源按 Workspace 查询；
- [ ] 双 Workspace 越权测试覆盖全部 CRUD；
- [ ] 旧全局模块普通用户不可访问；
- [ ] 导出、URL、富文本和 Webhook 防护完成；
- [ ] 模型任务有限流和预算；
- [ ] 敏感操作有审计；
- [ ] 日志不含 Token、密钥和不必要敏感内容。
