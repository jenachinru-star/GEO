# 接口契约与页面映射

## 1. 通用契约

API 前缀使用 /api/v2。列表响应统一包含 items、page、page_size、total；时间使用 UTC ISO 8601；ID 类型在同一资源内保持一致；布尔值不使用 0/1 字符串代替。

成功响应直接返回资源或 data 包装，项目需选择一种并全局统一。建议：业务成功直接返回资源；错误统一 error 对象。迁移期 V1 保持旧包装，V2 不继续使用 code=0。

每个响应头返回 X-Request-ID。创建 Run、ToolTask、ExportTask 支持 Idempotency-Key。

## 2. 会话与 Workspace

| API | 方法 | 权限 | 后端服务/表 | 前端 |
|---|---|---|---|---|
| /auth/login | GET | 匿名 | IAMService/SSOState | 登录跳转 |
| /auth/callback | GET | 匿名+state | IAMService/User/Session | 回调页 |
| /auth/session | GET | 已登录 | SessionService/User/WorkspaceMember | AuthProvider |
| /auth/logout | POST | 已登录 | SessionService/AuditLog | 用户菜单 |
| /workspaces | GET | 已登录 | WorkspaceService | Workspace 切换器 |
| /workspaces/{id}/members | GET/POST | owner | MemberService | 成员管理 |
| /workspaces/{id}/members/{userId} | PATCH/DELETE | owner | MemberService/Audit | 成员管理 |

GET /auth/session 返回 user、current_workspace、workspaces、capabilities 和 csrf_token/策略信息。前端以 capabilities 决定显示，后端仍独立鉴权。

## 5. 监测任务

| API | 方法 | 权限 | 后端 | 前端 |
|---|---|---|---|---|
| /monitor-runs | POST | editor | MonitorRunService | 新建采集 |
| /monitor-runs | GET | viewer | MonitorRunQuery | 任务列表 |
| /monitor-runs/{id} | GET | viewer | MonitorRunQuery | 任务详情/轮询 |
| /monitor-runs/{id}/cancel | POST | editor | MonitorRunService | 取消 |
| /monitor-runs/{id}/retry-failed | POST | editor | MonitorRunService | 重试失败项 |
| /monitor-runs/{id}/observations | GET | viewer | ObservationQuery | 结果表 |
| /observations/{id} | GET | viewer | ObservationQuery | 证据抽屉 |
| /observations/{id}/reanalyze | POST | owner/admin | AnalysisService | 重算 |
| /observations/{id}/review | POST | reviewer/owner | ReviewService | 人工纠错 |

创建 Run 请求字段：doctor_id、question_ids 或 filter、providers、mode、samples、region、locale、persona。后端返回 accepted run，不等待采集。

Run 详情字段：status、planned/succeeded/failed/refused、progress、estimated/actual cost、methodology_version、started/finished、error_summary。

Observation 详情字段：问题快照、平台、模型、模式、状态、回答、来源、分析、实体、尝试记录和安全错误信息。

## 7. 内容机会与内容

| API | 方法 | 权限 | 服务 | 页面 |
|---|---|---|---|---|
| /content-opportunities | GET | viewer | OpportunityQuery | 机会列表 |
| /content-opportunities/{id}/dismiss | POST | editor | OpportunityService | 忽略 |
| /content-opportunities/{id}/drafts | POST | editor | ContentGenerationService | 生成草稿 |
| /contents | GET | viewer | ContentQuery | 内容列表 |
| /contents/{id} | GET/PATCH | viewer/editor | ContentService | 查看/编辑 |
| /contents/{id}/versions | GET | viewer | ContentVersionQuery | 版本历史 |

| /contents/{id}/submit-review | POST | editor/reviewer | ReviewWorkflow | 提交下一阶段 |

PATCH 只允许修改正文、标题等可编辑字段并要求 expected_version；所有状态变化使用命令接口。每次修改生成版本并按规则使旧批准失效。

## 11. 现有页面迁移

- Dashboard.tsx：替换为 V2 汇总和行动入口；
- DataCenter.tsx：演进为 /visibility；
- Semantic.tsx：演进为 /questions；
- ContentHub.tsx：保留入口，内部换成 ContentItem；
- Profile.tsx：增加证据和版本；
- Monitor.tsx：旧品牌页，不复用为医生任务页，避免概念混杂；
- Knowledge.tsx/RAGChat.tsx/Competitor.tsx/Settings.tsx：移至 Legacy/Admin 或归档；
- SSOCallback.tsx：只处理状态展示和后端会话确认，不从 URL 持久保存长期 Token。

## 12. 请求到数据的完整示例

用户点击“开始监测”后的顺序：

1. 前端提交 POST /monitor-runs 和 Idempotency-Key；
2. Auth 解析 User/Session；
3. Workspace 依赖验证 editor；
4. Entitlement 检查配额；
5. MonitorRunService 冻结问题和方法；
6. 一个事务创建 Run 与 planned Observations；
7. 返回 202；
8. Worker 逐个领取 Observation；
9. ProviderAdapter 调用上游；
10. 保存原始结果或标准错误；
11. AnalysisPipeline 保存 Analysis/Citation/Entity；
12. RunAggregator 更新进度；
13. 前端轮询显示进度；
14. 完成后 Notification 写入；
15. DashboardQueryService 只聚合 succeeded 且可分析数据；
16. 用户点击指标查看 Observation 证据。

用户从机会发布内容后的顺序：

1. Opportunity 生成 draft；
2. ContentGenerationService 使用资料快照与证据；
3. ComplianceEngine 产生风险和 MissingFacts；
4. 用户编辑并提交审核；
5. ReviewWorkflow 校验状态；
6. reviewer 批准特定版本；
7. 创建 ToolTask；
8. Webhook/轮询/人工确认形成 Distribution；
9. 后续监测识别 canonical URL；
10. AttributionEvent 建立时间与证据关联；
11. 前端展示“发布后观察到的变化”，不宣称必然因果。

## 13. 契约验收

- [ ] 页面上的每个写操作都有明确 API 和权限；
- [ ] 每个 API 都能追到 Service、Repository 和 Workspace 表；
- [ ] 前端不直接决定关键状态和指标；
- [ ] 创建任务均幂等；
- [ ] 长任务返回 202；
- [ ] 错误使用正确 HTTP 状态；
- [ ] 列表筛选与总数由后端执行；
- [ ] 证据、版本和审计可追溯；
- [ ] 旧路由不会绕过 V2 权限。
