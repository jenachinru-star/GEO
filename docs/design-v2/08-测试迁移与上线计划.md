# 测试、迁移与上线计划

## 1. 实施原则

- 小批次、可验证、可回滚；
- 先修安全和数据真实性，再增加功能；
- 新旧链路短期并存，但不长期双写；
- 每阶段有入口条件、交付物、验收和停止条件；
- 任何“测试通过”必须能指向自动化测试或签字的人工用例。

## 2. 阶段 A：设计与影子验证

### 工作

1. 评审本目录文档；
2. 明确 Provider 能力和费用；
3. 建立 30 个问题和人工标注规则；
4. 运行影子采集；
5. 对当前分析器和新定义做误差报告；
6. 确认医疗内容分类与审核人员；
7. 输出最终 ADR。

### 不做

不改正式表、不删除页面、不切换指标、不宣传现有 AEO。

### 验收

产品边界、指标、Workspace、AEO 定义和合规状态机获得确认；影子实验数据可复查。

## 3. 阶段 B：工程与明确故障基线

### 后端

- 补齐 requests、PyJWT、openpyxl 等依赖或替换为统一依赖；
- 修复旧 Collector 缺失配置导致的崩溃，但不扩展旧功能；
- 修复完整导出缺失配置；
- 配置移除生产默认密钥；
- 创建 .env.example；
- 引入 lint、format、pytest；
- 固定健康检查和错误响应基线。

### 前端

- 修复下载认证；
- 统一 401；
- 安全解析本地状态；
- 增加 ErrorBoundary、404；
- 建立 Vitest/Testing Library/Playwright 基线；
- 设置构建 chunk 预算。

### CLI

冻结新功能；给危险全量操作增加显式确认和参数校验；决定修复认证还是归档。

### 验收

现有核心流程没有回归；确定性崩溃消除；CI 能稳定执行。

## 4. 阶段 C：安全与 Workspace 底座

### 工作

1. 引入 Alembic 基线；
2. 新增 Workspace/Member/Session/Audit；
3. 每个现有 User 创建个人 Workspace；
4. IAM 改用 provider+sub；
5. API 引入 WorkspaceContext；
6. 旧全局模块普通用户禁用；
7. Doctor/Semantic/Article/Distribution 回填 workspace_id；
8. 双 Workspace 越权测试。

### Feature Flag

WORKSPACE_AUTH_V2 控制新请求上下文。先内部账号，再全部用户。

### 停止条件

出现身份错误绑定、数据归属不确定、跨租户测试失败或无法回滚时，停止上线。

## 5. 阶段 D：新监测链路

### 工作

1. 新增 Run/Observation/Analysis/Citation/Entity 表；
2. 实现统一 Provider 接口；
3. 引入独立 Worker；
4. 新采集仅写新表；
5. 分析器对金标准回归；
6. 实现任务、结果和证据 API；
7. 运行至少一个完整影子周期。

### Feature Flag

MONITORING_V2_WRITE、MONITORING_V2_READ 分离。先打开写入验证，再打开内部读取。

### 验收

满足 01 文档精度门槛；失败 100% 从业务分母排除；任务可恢复；费用可追踪。

## 6. 阶段 E：前端指标切换

### 工作

- 新 Dashboard；
- 新数据中心与证据抽屉；
- Run 进度、重试、取消；
- 新问题分类；
- 移除误导性 AEO 唯一答案与饼图；
- 指标显示样本量和覆盖率。

先对内部用户开放，至少观察一个完整监测周期。旧页面仍可回退但只读。

## 7. 阶段 F：内容与发布闭环

### 工作

1. 新 ContentItem/Opportunity/Evidence/Review；
2. 迁移 ArticleDraft；
3. 生成器输出 Claim 和风险；
4. 上线审核状态机；
5. 外部工具 Adapter、任务和 Webhook；
6. Distribution URL 验证；
7. 发布后监测与归因事件。

旧 Content 停止写入。内容迁移先复制并对账，不直接删除源数据。

## 8. 阶段 G：归档和商业化验收

### 工作

- 完成历史数据所有权确认；
- 归档无法识别数据；
- 移除旧路由和导航；
- 更新 README、部署和运营文档；
- 合规专业复核；
- 完成安全测试、备份恢复和容量测试；
- 定义套餐配额和商业指标口径。

只有阶段 G 验收后，才允许以新指标进行正式商业承诺。

## 9. 自动化测试矩阵

### 9.1 后端单元测试

- 实体别名和医院消歧；
- 否定推荐；
- 排名未知；
- URL 解析与归属；
- 错误分类；
- Run 状态汇总；
- 内容状态机；
- 合规规则；
- Workspace Repository 自动过滤；
- 配额和幂等。

### 9.2 后端集成测试

- PostgreSQL Alembic 从空库升级；
- SQLite 旧库副本迁移；
- IAM state 一次性消费；
- 双 Workspace 全接口越权；
- Worker 崩溃恢复；
- Provider 模拟超时、429、5xx、拒答和无效 JSON；
- Webhook 签名和重放；
- Excel 公式注入；
- 导出归属。

### 9.3 前端测试

- 类型检查；
- 指标卡与覆盖率；
- API 错误映射；
- 权限路由；
- 任务轮询停止；
- Content 状态按钮；
- Workspace 缓存隔离；
- 移动端布局和可访问性。

### 9.4 E2E

1. 登录并初始化个人 Workspace；
2. 完善资料和证据；
3. 生成、确认语义问题；
4. 创建监测 Run；
5. 查看成功、失败和证据；
6. 从机会生成草稿；
7. 审核、退回、修改、批准；
8. 创建外部任务并登记发布；
9. 查看发布后引用事件；
10. 验证另一个 Workspace 无法访问。

## 10. CI 流水线

每个提交：后端格式/静态检查、pytest、前端 lint/typecheck/test/build、Go 测试或明确归档、Alembic 空库迁移、依赖漏洞检查、git diff check。

合并主分支：PostgreSQL 集成测试、Playwright 核心流程、构建制品、SBOM/依赖清单。

发布候选：旧库迁移演练、备份恢复、影子 Provider 测试、性能和安全检查。

## 11. 数据对账

每次迁移输出：源表行数、目标表行数、跳过数、冲突数、无法确定所有权数、字段映射差异、抽样校验和回滚点。

旧 doctor MonitorRecord 迁移时专门检查 question_id、semantic_id、detect_type、固定 round=99 和错误回答文本，不能盲目搬运为成功数据。

## 12. 发布策略

- 内部账号 → 5% Workspace → 25% → 100%；
- 每步至少观察任务成功率、错误率、指标差异和用户反馈；
- 数据写入开关与 UI 开关分离；
- 数据库收缩最后执行；
- 发布窗口内确保开发、产品和数据库负责人可处理回滚。

## 13. 回滚触发条件

- 跨 Workspace 数据可见；
- 采集失败被计算为业务失败；
- 新旧数据不可解释差异超过阈值；
- 任务重复导致明显额外成本；
- 内容绕过审核发布；
- IAM 大规模登录失败；
- 数据迁移出现无法恢复的丢失或错绑。

回滚优先关闭 Feature Flag 和停止新任务，不删除新数据。待根因确认后修复或恢复旧读链路。

## 14. 建议任务拆分

每个 PR 只解决一个可验收主题，参考：

1. 测试和 CI 基线；
2. 确定性运行错误；
3. Alembic 基线；
4. Workspace 表和回填；
5. IAM provider_subject 与 Session；
6. Workspace 依赖与越权测试；
7. 旧模块隔离；
8. Run/Observation 模型；
9. Provider 接口；
10. Worker；
11. 分析器与金标准；
12. V2 Dashboard API；
13. 前端认证和生成 API 类型；
14. V2 数据中心；
15. Content 状态机；
16. 合规规则；
17. 工具任务和 Webhook；
18. 历史迁移和旧模块归档。

避免把数据库、后端、前端、认证和页面重做放进同一个巨大 PR。

- [ ] 影子实验达到精度门槛；
- [ ] 全业务数据完成 Workspace 隔离；
- [ ] 监测使用新 Run/Observation；
- [ ] 内容生成和发布受审核门禁；
- [ ] 核心链路自动化测试通过；
- [ ] 迁移与恢复演练通过；
- [ ] 旧模块已归档或明确保留理由；
- [ ] 安全、隐私和医疗合规完成专业复核；
- [ ] README、部署、运维和用户帮助与实际系统一致。
