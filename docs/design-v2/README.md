# 医生个人品牌 GEO/AEO 平台 V2 设计文档

版本：2.0-draft  
状态：设计冻结阶段  
适用项目：GEO  
最后更新：2026-09-14

## 1. 文档目的

本目录定义项目从当前“医生产品与旧企业品牌平台混合”的状态，演进为“医生个人品牌 AI 可见度监测与合规内容优化平台”的完整方案。

本文档集是后续开发、评审、测试、上线和验收的唯一设计基线。实施人员不得只依据历史阶段报告或页面效果直接修改数据库和业务逻辑；任何偏离本方案的设计，需要先补充 ADR 决策记录并获得确认。

本阶段只形成设计，不直接迁移数据库、不删除旧模块、不改变线上指标。

## 2. 已确认的产品方向

1. 聚焦医生个人品牌，不同时建设通用企业品牌产品。
2. 使用 Workspace 作为业务数据归属边界，为医生助理和医院团队预留协作能力。
3. 将普通模型认知、联网搜索可见度、消费者前台抽检分层管理。
4. 严格区分请求成功、实体提及、明确推荐、排序、来源引用和唯一答案。
5. 只有存在可验证来源时才计算来源引用；没有来源 URL 时不得称为 AEO 引用。
6. 医疗科普与商业推广采用不同规则和审核流程。
7. 外部图文、视频、发布工具通过统一适配接口接入。
8. 采用模块化单体和独立采集 Worker，不引入微服务、Kafka 或 Kubernetes。
9. 旧品牌监测、旧 Content、旧 Knowledge/RAG、旧 Competitor 和 CLI 先隔离，完成数据确认后再决定迁移或归档。
10. 新指标验证完成前，现有 GEO/AEO 数据不得用于商业承诺。

## 4. 阅读顺序

实施前按以下顺序阅读：

1. 先读总体设计和指标规范，理解产品到底测量什么。
2. 再读数据模型，确认数据所有权和历史兼容策略。
3. 后端、前端分别依据实施手册拆任务。
4. 所有涉及账号、内容或发布的功能，同时遵守安全与医疗合规文档。
5. 最后依据测试迁移计划分阶段上线，不允许一次性替换全部旧逻辑。

## 5. 决策优先级

发生冲突时，按以下优先级裁决：

1. 数据安全和医疗合规；
2. 指标真实性与可解释性；
3. 数据一致性和可回滚性；
4. 用户体验；
5. 开发速度；
6. 技术先进性。

## 6. 变更管理

重大变更必须记录：问题、备选方案、选择、理由、影响、回滚方式和重新评估条件。建议在 docs/design-v2/adr 下按 ADR-0001、ADR-0002 编号维护。

以下事项属于重大变更：

- 改变 AEO、推荐率或可见度定义；
- 新增平台数据来源；
- 修改 Workspace 数据隔离；
- 修改内容发布门禁；
- 引入新的身份提供方；
- 从模块化单体改为分布式架构；
- 删除或合并历史表。

## 7. 当前设计假设

- 项目仍处于小团队/MVP 到早期生产过渡期。
- 首要用户是医生本人或其授权运营人员。
- 初期每个用户自动拥有一个个人 Workspace。
- 监测规模初期为每天数百到数千个模型请求。
- 医疗内容必须经过人工确认后才能视为可发布内容。
- 外部工具不一定都支持稳定 API 或 Webhook，因此保留人工确认通道。

若上述假设发生变化，应先更新总体设计和 ADR，再开始相应工程调整。
