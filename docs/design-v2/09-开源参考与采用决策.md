# 开源参考与采用决策

## 1. 采用原则

开源项目优先用于参考领域模型、指标、测试和工程规则，不因为功能列表丰富就直接引入依赖。采用前检查许可证、维护活跃度、数据发送范围、安全、部署成本和与医疗场景的适配性。

## 2. GEO/AEO 项目

### 2.1 Elmo

地址：https://github.com/elmohq/elmo

值得复用：品牌别名/域名、每个引用 URL 和位置、竞品 Share of Voice、Prompt 管理、query fan-out、来源分类。

采用方式：参考数据结构和产品交互，不直接替换当前后端。重点映射到 Citation、DetectedEntity、QuestionCluster 和 Dashboard。

### 2.2 aeo-platform

地址：https://github.com/webappski/aeo-platform

值得复用：多次采样、置信区间、错误与正常结果分离、缓存回答重放、区域、无品牌意图问题、CI 友好报告。

采用方式：把重复采样、Observation Replay 和错误退出语义写入本项目规则。

### 2.3 AEO Radar

地址：https://github.com/hellowalt/aeo-radar

值得复用：Keyword → Prompt → CrawlRun → Result → Analysis 分层，以及原始证据和意图问题设计。

不采用：大规模 UI 抓取作为核心数据源。原因是稳定性、账号风控和平台条款风险。

### 2.4 AutoGEO

地址：https://github.com/cxcscmu/AutoGEO

论文：https://proceedings.iclr.cc/paper_files/paper/2026/hash/dd5dfba659a7ec010414de1c1debdeb4-Abstract-Conference.html

值得复用：不同生成引擎和领域使用不同优化规则、以实验评估策略效用。

不采用：现阶段不引入训练和复杂自动规则学习栈，避免超出 MVP 运维能力。

### 2.5 geo-lint

地址：https://github.com/IJONIS/geo-lint

值得复用：规则化检查、结构化 JSON、可测试的修复建议、修复前后对比。

采用方式：未来构建 Content Readiness Linter，检查可抓取性、来源、作者、更新时间、结构化内容和声明风险。

### 2.6 geo-optimize-site Skill

地址：https://github.com/kyliamet/geo-optimize-site

值得复用：answer-first、crawlability、metadata、schema、sitemap、llms.txt、内部链接和验证清单。

采用边界：项目较新，应摘取规则并编写自己的测试，不直接赋予自动修改生产站点权限。

## 3. 基础设施

### 3.1 Alembic

地址：https://alembic.sqlalchemy.org/en/latest/

决策：立即采用。用于 SQLAlchemy 数据库版本、升级、降级、批处理迁移和迁移审查。自动生成只产生候选，必须人工复核。

### 3.2 LiteLLM

地址：https://docs.litellm.ai/

决策：暂不采用完整 Proxy。先实现本项目 Provider 接口。当平台数量、预算、回退和观测复杂度明显增加时，评估 SDK 或 Proxy。

### 3.3 Langfuse

地址：https://github.com/langfuse/langfuse

决策：阶段 D/E 再评估。适用于 LLM Trace、Prompt 版本、数据集和评估。医疗场景启用前需要自托管、脱敏和数据保留配置。

### 3.4 Ragas

地址：https://github.com/vibrantlabsai/ragas

决策：只有保留并重建 Workspace RAG 时采用评估思想。当前医生 GEO 主链不依赖 RAG，不提前引入。

### 3.5 pgvector

地址：https://github.com/pgvector/pgvector

决策：暂缓。当前知识数据量不需要向量数据库。若未来建立大规模证据库和语义检索，再基于 PostgreSQL 使用 pgvector，避免新增独立向量服务。

## 4. 身份与安全

### 4.1 Casdoor SDK

地址：https://casdoor.ai/docs/how-to-connect/sdk/

Python SDK：https://github.com/casdoor/casdoor-python-sdk

决策：优先使用官方 SDK 或标准 OIDC 库验证协议细节，减少自制 OAuth 的 state、token 和用户信息错误。是否替换现有 requests 实现需先验证当前 IAM 兼容性。

### 4.2 OWASP

会话与前端存储：https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html

公式注入：https://owasp.org/www-community/attacks/CSV_Injection

决策：作为认证存储、导出、URL、输入和安全测试的最低基线。

## 5. 搜索与内容官方依据

### 5.1 Google AI Features

地址：https://developers.google.com/search/docs/appearance/ai-features

采用结论：传统 SEO、可抓取、可索引、可靠且面向人的内容仍是基础；Google 不要求特殊 AI 文件或特殊 Schema；query fan-out 值得用于主题簇设计；收录和展示不做保证。

### 5.2 llms.txt

地址：https://llmstxt.org/

采用结论：可作为公开权威内容导航的补充协议，不作为排名或引用保证。当前需要公开可访问，不能放在登录保护下载接口后面。

### 5.3 智谱 Web Search

地址：https://docs.bigmodel.cn/api-reference/%E5%B7%A5%E5%85%B7-api/%E7%BD%91%E7%BB%9C%E6%90%9C%E7%B4%A2

采用结论：普通 Chat 与联网搜索明确分层；适配器需按能力声明来源和搜索模式，不能用同一个平台名称掩盖模式差异。

## 6. 医疗与隐私依据

- 《互联网广告管理办法》：https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_d93a579afd45413e8576e4623fab348f.html
- 《医疗广告管理办法》：https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/ggjgs/art/2023/art_6584dc1c94c2408db7c73f0b5e3d225a.html
- 《中华人民共和国个人信息保护法》：https://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html
- 《生成式人工智能服务管理暂行办法》：https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm

决策：规则进入内容分类、证据、人工审核、隐私最小化和 Provider 审查流程；正式上线前由专业人员核验最新法律和实际业务适用性。

## 7. 不建议直接复制的内容

- 把普通模型回答称为真实 AI 搜索排名；
- 用一个布尔值代表提及、推荐和引用；
- 依赖 localStorage 保存所有业务和认证状态；
- 把自动浏览器抓取作为唯一监测方式；
- 未审查就安装可自动修改站点的 Skill；
- 为少量数据立即引入微服务、向量数据库和完整 LLM 网关；
- 直接复制通用营销内容规则到医疗场景；
- 把开源项目的星数当作安全或正确性的证明。

## 8. 引入开源依赖的检查表

- [ ] 许可证允许当前商业使用；
- [ ] 依赖维护状态可接受；
- [ ] 无已知高危漏洞或已制定缓解；
- [ ] 不会把医疗/账号数据发送到未批准服务；
- [ ] 有锁定版本和升级策略；
- [ ] 有替换/退出方案；
- [ ] 只引入实际需要的能力；
- [ ] 有测试覆盖其关键行为；
- [ ] 文档记录采用版本和改动；
- [ ] 法律、隐私和平台条款已确认。
