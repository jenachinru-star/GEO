# 外部工具与发布闭环

## 1. 目标

建立从批准内容到外部制作、发布 URL、抓取状态和后续引用变化的稳定链路，不把核心业务绑定到某一个图文或视频工具。

## 2. 工具类型

- article_generator：图文排版/生成；
- video_generator：视频脚本或视频生成；
- publisher：向内容平台发布；
- analytics：获取阅读或互动；
- webmaster：站点抓取和索引数据。

一个工具可实现多个能力，但系统按能力而非品牌名称编排。

## 3. Adapter 接口

每个 Adapter 声明：

- code、display_name；
- capabilities；
- auth_type；
- supports_webhook；
- supports_cancel；
- allowed_domains；
- create_task；
- get_task_status；
- cancel_task；
- parse_webhook；
- validate_result。

Adapter 返回统一 ToolTaskResult，包含 external_task_id、status、result_url、artifacts、error_code 和 safe_message。

## 4. 任务生命周期

    created
      → submitted
      → processing
      → succeeded
      → result_confirmed

异常分支：failed、cancel_requested、cancelled、expired、manual_action_required。

任务状态与 Content 状态分离。外部任务失败不能把已批准内容自动改回草稿；内容修改也不能覆盖历史外部任务。

## 5. 创建任务

前置校验：

1. Content 当前版本为 approved；
2. 用户有 publish 权限；
3. 工具已启用且支持目标格式；
4. Workspace 配额足够；
5. 内容风险和目标平台规则通过；
6. Idempotency-Key 未使用；
7. 发送的是批准版本快照，而不是可继续变化的正文引用。

## 6. Webhook

接收步骤：

1. 限制请求体大小；
2. 校验工具标识、签名和时间戳；
3. 检查 event_id 防重放；
4. 保存脱敏原始事件；
5. 快速返回 2xx；
6. 异步更新 ToolTask；
7. validate_result 校验 URL、类型和外部任务一致性；
8. 创建或更新 Distribution；
9. 通知用户。

状态回退、未知任务和签名失败写安全日志，不直接把外部错误返回给用户。

## 7. 轮询

不支持 Webhook 时，Worker 按退避策略轮询。设置最大持续时间，超时进入 manual_action_required，不能无限轮询。

## 8. 人工回填

若外部工具无 API：

1. 创建本地 ToolTask 和一次性操作编号；
2. 跳转工具；
3. 用户返回粘贴发布 URL/作品 ID；
4. 后端校验协议、域名、重复和所有权信息；
5. 用户确认平台、发布时间和账号；
6. 创建 publish_mode=manual 的 Distribution；
7. 记录操作者和审计。

人工回填在分析与报表中明确标识，不伪装成平台验证数据。

## 9. 发布 URL 验证

- 仅 http/https；
- allowed_domains 白名单；
- 规范化 query、fragment 和短链接；
- 服务端抓取需防 SSRF；
- 保存 raw_url、canonical_url、final_url；
- 页面被删除或重定向时更新状态，不删除历史；
- 不把 URL 存在等同于内容已被索引。

## 10. 抓取和索引状态

发布后可以记录：reachable、crawl_allowed、indexed_known、last_checked_at。只有接入 Search Console 等权威数据时才标记 indexed=true；普通 HTTP 200 只能证明可访问。

Google 官方说明，进入 AI 搜索的页面首先需要能被 Google 索引并有资格显示摘要，但满足要求也不保证收录或展示：https://developers.google.com/search/docs/appearance/ai-features

## 11. 效果归因

发布前建立 baseline window，发布后设置观察窗口。匹配条件：目标问题、引用 canonical URL/域名、时间、Provider 和模式。

系统可表述：

- 发布后首次观察到该 URL 被引用；
- 发布后目标问题引用率由 A 变化到 B；
- 同期其他模型/来源也发生变化。

系统不能仅凭时间先后声称内容直接导致提升。需要保留其他内容发布、模型版本变化和采样方法变化作为混杂因素。

## 12. 前端操作

- 在 Content 详情中展示批准版本和可用工具；
- 创建任务前展示将发送的数据、费用和目标工具；
- 任务进度可离开页面；
- 失败显示可执行建议和重试条件；
- Webhook 成功自动进入发布记录；
- 人工回填有独立标识；
- 发布详情显示 URL、安全打开、验证状态和关联引用事件。

## 14. 验收

- [ ] 重复点击不会创建重复外部任务；
- [ ] Webhook 有签名、防重放和幂等；
- [ ] 外部失败不破坏内容批准状态；
- [ ] 手工回填有域名校验与审计；
- [ ] URL 存在不等同于已索引；
- [ ] 发布版本不可变；
- [ ] 引用事件可以关联发布 URL；
- [ ] 归因文案不误导因果。
