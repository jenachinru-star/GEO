# 指标与采集规范

## 1. 目标

本规范解决“系统究竟测量什么、结果是否可信、失败如何处理、AEO 如何定义”的问题。所有后端字段、前端文案、图表和商业说明必须与本规范一致。

## 2. 基础术语

### 2.1 Provider、Model 与 Mode

- Provider：服务提供方，例如智谱、MiniMax、DeepSeek。
- Model：实际调用的模型及版本。
- Mode：chat、grounded_search、consumer_audit。
- Observation：一次问题、平台、模型、模式和采样序号对应的一次原始观测。
- Analysis：对 Observation 的可重放结构化分析。

Provider 名称不能被直接解释为消费者产品名称。例如调用某厂商开放 API，并不能自动代表其网页或 App 前台结果。

### 2.2 成功状态

Observation 状态：pending、running、succeeded、failed、cancelled、expired。

失败需保存标准错误码：

- auth_error：密钥或权限错误；
- rate_limited：限流；
- timeout：超时；
- provider_5xx：平台服务错误；
- invalid_response：响应结构无效；
- safety_refusal：安全拒答；
- content_filtered：内容过滤；
- budget_exceeded：预算上限；
- cancelled：任务取消；
- internal_error：系统内部错误。

failed、cancelled、expired 不进入可见度分母。safety_refusal 是否进入有效回答分母由产品单独展示，默认不进入提及率，但计入“拒答率”。

## 3. 问题体系

### 3.1 问题分类

| intent_type | 说明 | 示例 | 主要用途 |
|---|---|---|---|
| discovery | 不带医生名的发现问题 | 上海擅长某疾病的医生有哪些 | 真实获客可见度 |
| branded | 带医生名的核验问题 | 张某医生擅长哪些疾病 | 实体信息正确性 |
| comparison | 候选比较或选择 | 治疗某疾病如何选择医生 | 推荐与竞品分析 |
| informational | 健康知识问题 | 某症状通常需要哪些检查 | 来源引用与内容机会 |
| navigational | 找医生主页或渠道 | 张某医生在哪里出诊 | 实体一致性和渠道 |

### 3.2 题目约束

每条 SemanticQuestion 至少包含：

- workspace_id；
- doctor_id；
- question_text；
- intent_type；
- branded 布尔值；
- region_code；
- locale；
- persona，可为空；
- source_type：generated、manual、imported、fanout；
- version；
- active 状态；
- created_by。

问题文本保存时应去除首尾空白、统一连续空格；同一 Workspace、医生、规范化文本和版本必须唯一。

### 3.3 生成规则

自动生成不能只根据医生姓名和专业拼接。生成步骤：

1. 从医生资料取得已验证的地区、科室、擅长领域；
2. 先生成主题簇，再生成不同意图问题；
3. branded 与 unbranded 分组；
4. 去除诊断诱导、治疗承诺、患者隐私和不实资历；
5. 人工确认后启用；
6. 保存生成器版本和输入资料版本。

医生资料发生变化时，不直接删除旧问题。标记旧问题需要复核，用户确认后创建新版本。

## 4. 指标定义

### 4.1 请求成功率

请求成功率 = succeeded Observation 数 / 计划 Observation 数。

必须同时展示计划数、成功数、失败数、拒答数。请求成功率低于设定阈值时，禁止只展示可见度涨跌结论。

### 4.2 实体提及率

提及率 = 成功且可分析回答中，明确命中目标医生实体的回答数 / 成功且可分析回答数。

命中要求：

- 命中医生完整姓名或经确认的医生别名；或
- 姓名与医院/科室组合能唯一归属目标医生。

单独出现医院名称、科室、城市、职称或自我介绍片段均不能算医生命中。

### 4.3 推荐率

推荐率 = 成功回答中，存在明确推荐关系的回答数 / 成功回答数。

明确推荐包括“推荐、建议选择、可以考虑、候选医生”等正向关系。以下不算推荐：

- 新闻或履历中的普通提及；
- “不建议选择”或风险警示；
- 用户问题中原样重复姓名；
- 免责声明或来源列表中出现姓名。

### 4.4 排名

只有回答存在明确有序列表或顺序语言时才记录 rank。无法确定时 rank 为 null，绝不能默认 1。

第一推荐率 = 明确 rank=1 且 recommendation=true 的成功回答数 / 成功回答数。

### 4.5 来源引用率

来源引用成立需同时满足：

1. 回答返回可验证 URL 或平台提供的结构化 source；
2. source 与回答中的事实或推荐存在关联；
3. source 能正常规范化为 http/https URL；
4. source 不是平台错误页、搜索结果跳转空页或无关页面。

来源引用率 = 含至少一个有效来源的成功回答数 / 成功回答数。

进一步拆分：

- owned citation：医生官网、医院权威主页、医生控制的已认证渠道；
- earned citation：媒体、学术机构、百科、第三方平台；
- competitor citation：竞品医生或其所属页面；
- unrelated citation：与目标无关，保留但不计入目标引用。

### 4.6 AEO

V2 中 AEO 不再是一个模糊布尔值。产品层显示为“来源引用表现”，由以下指标组成：有效引用率、自有来源引用率、权威第三方引用率、引用域名数和引用位置。

如果业务仍需保留 AEO 标签，则 AEO 成功定义为：目标医生或其权威内容成为回答事实的可验证来源。只有提及或推荐不满足该定义。

### 4.7 唯一答案

只有结构化分析确认回答中不存在其他同类候选，且目标医生为唯一明确推荐对象时，才可标记 sole_recommendation=true。前端默认不使用“唯一答案”文案。

### 4.8 Share of Voice

医生推荐声量 = 目标医生推荐次数 / 所有被识别医生推荐次数。

该指标必须限定相同问题集、时间段、平台、模式和采样策略，不能跨不同采样集合比较。

### 4.9 一致性

同一问题、平台、模式至少多次采样：

- mention_consistency：提及结果相同的比例；
- recommendation_consistency：推荐结果相同的比例；
- citation_consistency：来源域名重复出现的稳定程度。

样本少于三次时，不显示“稳定”结论。

## 5. 采样规范

### 5.1 最小采样单元

唯一采样单元由 workspace、doctor、question_version、provider、model、mode、region、locale、persona、prompt_version、sample_index 组成。

### 5.2 默认策略

- 日常追踪：重点问题每平台每模式 3 次；
- 全量基线：每平台每模式 5 次；
- 消费者抽检：每月或发生重大变化时人工采样；
- 失败重试：最多 2 次指数退避，但每次尝试记录在 request_attempt；
- 温度：按监测模式固定，不能在共享适配器实例上临时修改；
- 超时：按平台配置，超时视为失败而非未提及。

### 5.3 可比性

趋势比较要求问题版本、平台、模式、地区和采样数一致。如果模型版本或 Prompt 版本变化，前端显示“方法变化”标记并分段趋势。

## 6. Prompt 设计

监测 Prompt 由三部分组成：

1. 用户原始问题；
2. 最小必要环境，例如地区和语言；
3. 平台所需的搜索开关或结构化返回要求。

禁止为了让目标医生出现而在无品牌问题的系统提示中注入医生姓名。分析阶段也不得把目标医生资料传给待测模型，避免污染回答。

Prompt 模板需要版本化，保存 template_id、version、hash 和变更原因。

## 7. 分析流程

### 7.1 分层分析

第一层确定性规则：URL 解析、实体别名精确匹配、有序列表、平台结构化 sources。

第二层结构化 LLM 判断：推荐关系、否定关系、候选边界、事实与来源关联。要求 JSON Schema 输出，低置信度进入人工复核。

第三层人工抽检：维护标注数据集，持续计算分析器精度。

### 7.2 分析输出

每次 Analysis 保存：

- analyzer_version；
- target_mentioned；
- mention_evidence；
- recommendation；
- recommendation_evidence；
- rank，可为空；
- sentiment：positive、neutral、negative、mixed、unknown；
- sole_recommendation；
- competitors 数组；
- citations 数组；
- confidence；
- review_status；
- analyzed_at。

不得保存或展示模型私有推理过程，只保存必要的可解释证据片段。

## 8. 来源处理

URL 进入系统后执行：

1. 仅允许 http/https；
2. 移除常见追踪参数；
3. 解析 canonical URL；
4. 规范化域名和国际化域名；
5. 记录原始 URL 与规范化 URL；
6. 识别来源所有权和类型；
7. 可选异步检查状态码、标题、发布时间和作者；
8. 不主动抓取 robots.txt 禁止的内容。

## 9. 影子实验

### 9.1 目的

在正式切换指标前验证新分析器和采集方式，不写入旧 MonitorRecord，不影响当前 Dashboard。

### 9.2 测试集

建立至少 30 个问题：12 个 discovery、6 个 branded、6 个 comparison、6 个 informational。每个问题在至少三个 Provider 上采样三次。

### 9.3 人工金标准

两名标注者分别标注提及、推荐、排名、来源、竞品和错误；意见冲突由第三人裁决。若人力有限，至少双人复核所有疑似 AEO 成功样本和 20% 随机样本。

### 9.4 上线门槛

- 提及 Precision ≥ 0.95，Recall ≥ 0.90；
- 推荐 Precision ≥ 0.90；
- 来源引用 Precision ≥ 0.95；
- 平台错误从业务分母排除率 100%；
- 任意结果可追溯原始回答、平台、模型、问题版本和分析器版本；
- 同一基线重复运行能解释差异原因。

未达到门槛时只能显示实验结果，不替换正式口径。

## 10. 前端展示规则

- 所有比例旁显示 n/N；
- 显示成功覆盖率，低覆盖使用警告色；
- 趋势切换时标注模型或方法变化；
- 提及、推荐、来源引用使用不同标签和颜色；
- 排名未知显示“未形成明确排序”，不能显示第 1；
- 点击指标可展开证据；
- 不使用“保证、唯一、权威第一”等绝对化文案；
- 普通模型基准与联网搜索结果不得画在同一条无区分趋势线上。

## 11. 验收检查表

- [ ] 数据库能区分成功、失败、拒答和取消；
- [ ] 失败不进入可见度分母；
- [ ] 医院单独出现不会命中医生；
- [ ] 无序回答 rank 为 null；
- [ ] 无 URL 不会成为来源引用；
- [ ] 问题按意图与 branded 分组统计；
- [ ] 多次采样有一致性指标；
- [ ] 页面展示样本量和成功覆盖率；
- [ ] 分析结果支持离线重放；
- [ ] 影子实验达到上线门槛。
