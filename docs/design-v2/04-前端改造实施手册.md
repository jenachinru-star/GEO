# 前端改造实施手册

## 1. 改造目标

前端需要从“展示几个统计卡片并同步等待接口”升级为能够清楚解释证据、任务状态、样本质量和医疗内容审核的产品界面。

核心原则：后端负责业务真相，前端负责呈现和交互；前端不自行重新计算关键指标，不通过隐藏菜单代替权限，不把 API 失败当空数据。

## 3. API 客户端

### 3.1 frontend/src/api/index.ts

拆分为 client.ts 和按领域生成的 API。修复事项：

- 下载接口使用同一个认证客户端；
- 统一处理 401：清理本地状态并进入重新认证；
- 处理 FastAPI detail 和 V2 error.message；
- 统一 request_id，错误提示可提供排查编号；
- 只对幂等请求自动重试；
- POST 创建任务通过 Idempotency-Key 防止重复点击；
- validateStatus 和 blob 错误解析一致；
- API Base URL 从环境读取，不硬编码内网地址。

建议从 FastAPI OpenAPI 生成 TypeScript 类型和请求函数，减少 any 与字段漂移。生成文件禁止手改，包装层处理 UI 适配。

### 3.2 前端类型

关键类型必须显式：Workspace、DoctorProfile、SemanticQuestion、MonitorRun、Observation、Analysis、Citation、ContentItem、Review、Distribution、ApiError。

CI 中运行 TypeScript strict 和 API 生成差异检查。

## 4. 身份和路由

### 4.1 store/useStore.ts

- 不在模块加载时直接 JSON.parse 未验证的 localStorage；
- 若采用 HttpOnly Cookie，store 不再保存 JWT；
- 只保存经过 Schema 校验的 UserSummary、WorkspaceSummary 和 UI 偏好；
- 增加 authStatus：unknown、authenticated、anonymous；
- 页面初始化先调用 /auth/session，再决定路由；
- logout 调用服务端注销后清空状态。

### 4.2 router/index.tsx

- RequireAuth 不再只检查 token 是否存在；
- MainLayout 本身也应在认证边界内，避免未登录时先渲染业务壳；
- 增加 RequireWorkspaceRole；
- 旧 monitor、knowledge、competitor、rag、settings 路由通过 Feature Flag 和角色限制，而非只隐藏菜单；
- 增加 403、404、系统异常页；
- 路由级 lazy loading 保留；
- 页面访问权限从后端 session/capabilities 返回，前端不硬编码唯一真相。

## 5. 全局交互

### 5.1 Layout.tsx

- Workspace 切换器：个人用户默认只有一个，不增加干扰；
- 导航调整为概览、AI 可见度、问题库、内容中心、医生资料；
- 管理员入口独立；
- 通知铃接真实 notification API，否则不展示假数字；
- 全局刷新改为刷新当前数据，不使用整页 reload；
- 移动端使用抽屉侧栏；
- 所有按钮、菜单和弹窗支持键盘和可访问标签。

### 5.2 通用状态

每个数据页统一提供：加载骨架、空状态、错误状态、重试、权限不足、数据过期提示。不能 catch 后静默展示 0。

## 6. Dashboard

### 6.1 信息层次

第一行不是简单 GEO/AEO 大数字，而是：

- 有效提及率 n/N；
- 明确推荐率 n/N；
- 有效来源引用率 n/N；
- 请求成功覆盖率 succeeded/planned。

每张卡包含统计周期、模式、样本量、与上期可比性状态。低覆盖时显示警告，不显示误导性涨跌。

### 6.2 图表

- 平台率不是组成关系，删除当前饼图；
- 平台比较使用分组柱状图或点图；
- 时间变化使用折线图，并按 chat/grounded_search 分面；
- 模型、Prompt 或方法版本变化处显示断点标记；
- 图表 Tooltip 显示分子、分母、失败数和置信信息；
- 颜色不能只靠红绿表达。

### 6.3 行动区

展示优先内容机会、异常平台、待审核内容和最近任务。每个机会应有“为什么推荐”和证据入口。

Dashboard.tsx 与 DataCenter.tsx 不再各自重复请求和统计，使用统一查询 Hook。

## 7. AI 可见度数据中心

建议替代现有 DataCenter：

### 7.1 顶部筛选

时间、监测模式、Provider、问题意图、是否带品牌、地区、任务批次和状态。

### 7.2 结果表

列：问题、模式、平台、成功状态、提及、推荐、排名、有效来源、竞品、采样一致性、采集时间。

失败显示明确错误标签；排名未知显示“无明确排序”；没有来源显示“未发现可验证来源”，不显示 AEO 失败的绝对结论。

### 7.3 证据抽屉

点击一行展开：

- 原始问题和回答；
- 平台、模型、模式和时间；
- 医生实体命中片段；
- 推荐证据；
- 来源 URL、域名、归属和位置；
- 竞品实体；
- 分析器版本与置信度；
- 人工纠错入口。

### 7.4 任务页

提供 MonitorRun 列表和详情：queued/running/partial/success/failed/cancelled，显示进度、预计成本、失败分布、重试失败项和取消。

前端通过轮询或 SSE 获取进度；初期轮询 3 至 5 秒即可，任务完成后停止。暂不需要 WebSocket。

## 8. 语义问题库

Semantic.tsx 改动：

- 分类 Tab：发现、品牌核验、对比、科普、导航；
- 显示 branded、地区、来源、版本和状态；
- 自动生成先进入草稿选择，不直接全部启用；
- 服务端搜索和分页，不能只过滤当前页；
- 批量启停/归档前显示影响范围；
- 资料变化导致 needs_review 时突出显示；
- 每个问题展示最近覆盖、提及、推荐和来源引用概况；
- 删除改为归档，有历史数据时说明不能物理删除；
- “付费新增”入口改成配额提示或正常新增，不保留未实现的付费文案。

## 9. 医生资料

Profile.tsx 分区：基础身份、执业机构、专业领域、别名、公开权威来源、账号协作。

要求：

- 显示字段验证状态和证据 URL；
- 别名明确说明用途，医院名不能独立作为医生别名；
- 表单保存使用 version，冲突时提示刷新和合并；
- 修改会影响语义问题时给出预览；
- 名字已包含“医生”时不重复拼接；
- 不收集与产品无关的患者敏感信息。

## 10. 内容中心

ContentHub.tsx 改为统一 ContentItem：

### 10.1 列表

服务端筛选 title、status、content_type、format、risk_level、reviewer、date。总数、已发布、已通过和待审核都由后端聚合，不能用当前页数组计算。

### 10.2 编辑器

界面同时展示正文、目标问题、医生资料快照、证据来源、风险提示和版本。关键事实点击可查看其 Evidence。

### 10.3 审核状态

根据权限展示提交事实检查、请求医学审核、请求合规审核、批准、退回。不能通过普通编辑表单直接把 status 改成 published。

内容被修改后，界面明确提示旧审核已失效。

### 10.4 发布

只有 approved 内容可以创建外部工具任务或登记发布。若外部工具失败，内容仍保持 approved，Distribution 单独为 failed。

## 11. 内容机会页

新增机会列表，按以下因素排序：

- 高价值 discovery 问题未提及；
- 竞品有权威来源而目标没有；
- 目标被提及但没有自有来源；
- 医生信息不一致；
- 重要来源过期或无法访问。

每个机会展示证据、预期目标、建议内容类型和“忽略原因”。不能承诺发布后必然提升排名。

## 12. 外部发布和归因

- 工具任务显示 processing/success/failed；
- 支持离开页面后继续运行；
- 外链统一校验 http/https，打开时使用 noopener/noreferrer；
- 人工回填 URL 时校验渠道域名并二次确认；
- 发布记录展示首次发现引用、引用来源变化和监测时间；
- 归因文案使用“发布后观察到”，避免直接表述因果。

## 13. 管理员页面

Settings.tsx 拆为管理员功能：Provider 健康状态、能力矩阵、配额、失败任务、合规规则版本、用户状态和审计。普通医生不可通过直接 URL 进入。

密钥只能显示是否配置和末尾少量字符，永不回传完整密钥。

## 14. 性能

- 页面按路由拆包；
- ECharts、富文本编辑器按需加载；
- Ant Design 避免全量图标和不必要依赖；
- 长表格服务端分页或虚拟化；
- 请求缓存按 Workspace 和筛选键隔离；
- 切换 Workspace 时清空上一个 Workspace 的缓存；
- 构建中对超大 chunk 设置预算并在 CI 监测。

## 15. 测试

### 15.1 单元/组件

- 指标卡 n/N、低覆盖、不可比状态；
- RequireAuth 与 RequireRole；
- 401、403、404、429、502 错误处理；
- Content 状态按钮；
- URL 安全校验；
- localStorage 损坏不崩溃。

### 15.2 E2E

- SSO 回调成功/失败/过期；
- 创建并观察监测 Run；
- 失败重试；
- 查看原始证据；
- 语义草稿确认；
- 内容审核与修改后批准失效；
- 外部任务失败与人工回填；
- Workspace A 无法访问 Workspace B；
- 移动端核心流程。

## 16. 前端完成定义

- [ ] 不再通过 Token 是否存在判断真实登录；
- [ ] 隐藏路由有后端和前端双重授权；
- [ ] 导出携带认证并正确处理错误；
- [ ] 关键指标来自服务端且展示 n/N；
- [ ] 失败不显示为零值；
- [ ] AEO 文案与来源证据一致；
- [ ] ContentHub 使用服务端全量统计；
- [ ] 任务可离开页面继续；
- [ ] 所有外链安全；
- [ ] 关键流程有 E2E；
- [ ] 桌面和移动端可用。
