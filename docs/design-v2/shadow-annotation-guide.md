# 影子实验人工标注指南

## 1. 基本原则

标注的是回答实际表达，不是标注者认为医生是否优秀。不要根据目标身份推测模型意图；没有证据就选择 unknown/false。

## 2. 字段

### request_valid

回答是否是完整、可分析的业务回答。超时、鉴权、空响应、系统错误为 false；安全拒答单独 refusal=true。

### target_mentioned

回答正文明确出现目标医生完整姓名/确认别名，或姓名加机构上下文能唯一识别。只有医院、科室或用户问题中的姓名不算。

### recommendation

回答明确建议、推荐、列为候选或给予正面选择关系。普通履历、引用列表、否定建议和无关提及不算。

### rank

只有明确有序列表或“首选/第一”等顺序语言才填写正整数；无法确定留空。

### sole_recommendation

回答明确只给出目标医生一个同类候选，且没有其他医生推荐时为 true。仅重点描述目标但同时列出他人时为 false。

### citations

逐条记录 URL、标题、域名、是否支持相关事实、是否关联目标医生、来源所有权。正文写“据资料”但无 URL 不算可验证来源。

### sentiment

positive、neutral、negative、mixed、unknown。否定风险和不建议选择必须反映在 recommendation=false 或 sentiment 中。

### competitors

记录回答中其他被推荐医生，不把医院、科室或疾病当竞品。

## 3. 双人复核

所有机器判为来源引用、唯一推荐、第一名、负面结果的样本必须双人复核；其余至少随机 20%。冲突由第三人裁决并记录 adjudication_note。

## 4. 隐私和安全

标注文件不包含 API Key、请求头、患者姓名、病历或联系方式。原始回答如果意外含敏感信息，应标记 privacy_flag 并存入受控位置，不进入 Git fixture。

## 5. 质量门槛

以裁决后的标签作为金标准，分别计算提及、推荐、排名、来源和唯一推荐。只报告有足够阳性与阴性样本的指标，避免小样本虚高。
