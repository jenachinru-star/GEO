GEO中台「内容中心 / 发布管理」现状数据流

按实际前端 + 后端代码绘制（基于 ContentHub.tsx / Distribution.tsx / article.py / distribution.py / asset_publish.py）

① 内容中心 ContentHub（/content）

创作工作台 选监测语义 → 拼URL → window.open() 跳到外部文章工具
ops.szcczh.com/paper-next/、video.szcczh.com
本系统不生成文章，只是个跳转入口
文章草稿表 ArticleDraft /api/v1/article CRUD
关联 semantic_id，自动跑 实体一致性校验（医生头衔/医院/职称）
内容机会 opportunityApi AI未提及 / 缺引用 / 排名靠后 → 给写作建议
▼ 写完回来登记

② 发布管理 Distribution（/distribution）

ArticleDistribution 状态机 /api/v1/distribution
draft → scheduled → processing → published / failed → removed
状态流转全部由人点按钮触发
⚠ 关键断点：没有外部API调用 点"标记已发布"弹窗原文：
"请确认已在「XX平台」手动发布了这篇文章"
publish_url = 人工粘贴
external_task_id 字段已建但全代码无人使用
科普发布线 AssetPublished（asset_publish.py） 从知识库文档 → GLM改写 → 存草稿
"保存即发布" = 本地 status 改 published，同样不发往外部
▼ 人工去平台发完 → 回来贴链接

③ 效果闭环（唯一有真实价值的部分）

effect 接口 /distribution/{id}/effect
按 published_at 切分 MonitorRecord：
· 发布前提及率/引用率/平均排名
· 发布后同名指标
· 30天趋势对比
recollect 接口
触发 monitor_collect 异步任务重新采集，验证AI是否开始引用
↑ 数据回流，闭环成立

③ 外部发布平台（当前对接状态）

百家号 大鱼号 企鹅号 搜狐号 网易号 微信公众号 知乎 小红书 豆瓣 脉脉 好大夫 丁香园 医脉通 寻医问药
这些平台清单目前是前端硬编码常量（useStore.ts 里的 PUBLISH_PLATFORMS），只用于打标签和展示合规规则，没有一个有真实的接口调用代码。
已实现且有真实数据流 半人工（登记/跳转） 未对接，依赖人工操作
一句话现状：这是一个"GEO监测 + 内容管理 + 发布登记台账"系统，不是"一键分发系统"。 真正的发布动作 100% 在系统外完成。
